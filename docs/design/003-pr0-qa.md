## 四、修复项逐项验证（CDP 实测）

### 4.1 三按钮与「应用并继续」

- 弹窗按钮实测：`["取消","丢弃并继续","应用并继续"]`（刷新、切表、切连接、切视图、DDL 六类入口一致）。
- 「取消」：pending 保留、单元格草稿保留、页码/排序/表名/连接/视图不变。
- 「丢弃并继续」：pending 清空并重新查询。
- 「应用并继续」（刷新）：请求携带原值 `C:\temp\new 'O''Reilly' 中文 😀`（未拼接 SQL），pending 清空，随后重查；`__dbQueries` 1→2。
- 「应用并继续」（切表）：先按 users 写库，再切到 orders 重查；data tab 为 orders、pending=0。
- 「应用并继续」（切连接）：写库后进入 Redis，key 列表 13 项。
- 「应用并继续」（切视图）：写库后 DBView 卸载，进入终端视图。
- 应用失败中止：模拟 `update_failed` 后切表被中止，data tab 仍为 users、pending=1、未发出 orders 查询、toast 显示 `Error: update_failed: simulated failure`。
- 写入期间冻结：`tab.loading=true` 时 ✓/✕ 按钮 disabled，点击单元格不出现输入框（上一轮 P28 的 FAIL 是断言未等 Vue tick，复测 disabled=true）。

### 4.2 DDL 保护

- 有 pending 时单击同表/异表打开结构标签：均先弹三按钮保护；取消后停留数据标签、pending=1、未创建/切换结构标签。
- 结构标签内点「DDL」：先保护；取消后仍是「基本」视图，不出现 DDL 面板。
- 结构标签内删列（执行 ALTER）：先保护；取消后不出现 SQL 预览、无 DDL 执行。
- `loadDDL` 改为返回 boolean，只有加载成功才切 `structView='ddl'`，不会出现空 DDL 面板。

### 4.3 错误码与 vitest

- 后端稳定码已落地：`invalid_update` / `too_many_updates` / `unknown_column` / `pk_mismatch` / `metadata_failed` / `update_failed` / `db_not_ready`。
- `npm test`：`dbEditing.test.ts` 6 用例全过（pending 计数、反斜杠/引号原值、NULL 映射、复合主键、行序稳定、失效行/列跳过）。
- 未完成：前端仍未按 code 映射 i18n（R5）；错误码命名与设计文档不一致（R4）。

## 六、剩余缺陷（均非阻塞）

### R1
- 严重度：一般
- 复现步骤：任意未保护地修改 `activeId`（当前仅程序化路径）且存在 pending。
- 期望：设计 §3.3.8 要求 `watch(activeId)` 检测到 pending 时记录错误并**拒绝清空**，作为漏保护的硬兜底。
- 实际：只 `console.warn`，随后照常 `tabs.value = []`，pending 随标签丢失。
- 证据/定位：`frontend/src/components/DBView.vue:1199-1205`。当前所有用户路径都经过 `guardPendingTabs`，故未复现真实丢失。

### R2
- 严重度：一般
- 复现步骤：修改一个单元格 → 点 ✓ 应用（写库成功）→ 让随后的重查失败（预览中覆写 `DBQuery` 抛 `query_failed`）。
- 期望：验收 §7.6 要求提示「修改已应用；查询失败，显示的是上一次结果」并提供刷新。
- 实际：toast 显示「已应用 1 条更新」，随后 `query-error` 显示 `query_failed`，`result=null`、pending=0；页面没有任何「修改已应用」提示（实测 `bodyHasAppliedHint=false`）。用户可能误以为写入未生效并重复操作。
- 证据/定位：`loadTableData` 的 catch 不向上抛错（`DBView.vue:434-439`），`applyEdits`/`guardPendingTabs` 无法区分「写库成功但重查失败」。

### R3
- 严重度：一般（既有问题，非本分支引入）
- 复现步骤：打开数据标签查看页大小下拉框。
- 期望：可交互下拉框，页大小保护可被用户触发。
- 实际：DOM 为未解析的 `<n-select>` 自定义元素（无 `.n-base-selection`）；用户无法改页大小。
- 证据/定位：`frontend/src/components/DBView.vue:5` 未导入 `NSelect`，模板 `:1412` 使用 `<n-select>`。`main` / `feat/v0.3-database` 同样存在。

### R4
- 严重度：轻微
- 复现步骤：对比设计 §4.4/§4.5 的稳定错误码表与实现。
- 期望：`too_many_edits`、`apply_edits_failed`。
- 实际：实现为 `too_many_updates`、`update_failed`（另新增 `metadata_failed`、`invalid_update`、`pk_mismatch`、`db_not_ready`）。
- 影响：错误码是稳定接口，前端 `db.err.<code>` 映射与文档需二选一对齐，避免上线后再改名。
- 定位：`internal/db/mysql.go:346-353`；设计文档 §4.4/§4.5。

### R5

- 复现步骤：触发任一更新错误，观察 toast。
- 期望：验收 §7.7 要求前端按 `code` 映射 i18n，未知 code 兜底 + 原文。
